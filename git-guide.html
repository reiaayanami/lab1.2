Системи Контролю Версій

Що таке система контролю версій?

Система контролю версій (Version Control System, VCS) — це програмне забезпечення, яке відслідковує та керує змінами в коді та інших файлах проекту. Вона дозволяє розробникам:

  • Зберігати історію всіх змін у проекті
  • Повертатися до попередніх версій коду
  • Працювати спільно з іншими розробниками
  • Розуміти, хто зробив які зміни та коли
  • Розгалужувати проект для експериментів

Типи систем контролю версій

Централізовані VCS (CVCS): Один центральний сервер зберігає всю історію (SVN, Mercurial)

Розподілені VCS (DVCS): Кожен розробник має повну копію репозиторію (Git, Mercurial)

Git — Розподілена Система Контролю Версій

Історія Git

Git був створений в 2005 році Лінусом Торвальдсом для управління проектом Linux kernel. Завдяки своїй простоті, швидкості та гнучкості, Git став найпопулярнішою системою контролю версій в світі.

Основні характеристики Git:

  • Розподіленість: Кожен розробник має повну копію проекту
  • Швидкість: Більшість операцій виконуються локально та миттєво
  • Гнучкість: Підтримка різних рабочих процесів (workflow)
  • Надійність: Контрольні суми та цілісність даних
  • Безпека: Використання SHA-1 хешування
  • Популярність: Інтеграція з GitHub, GitLab, Bitbucket

Основні Переваги Використання Git

📦 Локальна робота

Працюйте без інтернету. Всі операції виконуються на вашому комп'ютері з повною історією.

🚀 Висока швидкість

Git операції надзвичайно швидкі навіть для великих проектів завдяки локальному зберіганню.

👥 Командна робота

Легко colabor з іншими розробниками без конфліктів завдяки гнучкому merge механізму.

🌿 Гілки (Branches)

Створюйте ізольовані гілки для нових функцій без впливу на основний код.

⏮️ Повна історія

Повна історія проекту дозволяє відстежити еволюцію коду та повернутися до будь-якої версії.

🔍 Детальне відстеження

Бачте, хто змінив що, коли і чому завдяки детальним повідомленням commit.

10 Базових Команд Git

1. git init
$ git init Ініціалізує новий репозиторій Git у поточній папці. Створює прихову папку .git
2. git clone
$ git clone <url-репозиторію> Копіює (клонує) існуючий репозиторій з сервера на ваш локальний комп'ютер
3. git add
$ git add <назва-файлу> або $ git add . Додає файли до staging area (індекс) для підготовки до commit. "." додає всі змінені файли
4. git commit
$ git commit -m "Опис змін" Збергає snapshot поточного стану проекту з повідомленням про внесені зміни в локальний репозиторій
5. git push
$ git push origin <назва-гілки> Завантажує ваші локальні commit на віддалений сервер (GitHub, GitLab тощо)
6. git pull
$ git pull origin <назва-гілки> Завантажує последні зміни з віддаленого репозиторію та об'єднує їх з вашою локальною гілкою
7. git branch
$ git branch або $ git branch <назва-нової-гілки> Показує список всіх локальних гілок або створює нову гілку для розробки нової функції
8. git checkout
$ git checkout <назва-гілки> Переключається на іншу гілку або версію коду. Часто комбінується: git checkout -b для створення та переходу
9. git merge
$ git merge <назва-гілки> Об'єднує зміни з іншої гілки в поточну гілку. Використовується для завершення розробки функції
10. git status
$ git status Показує поточний стан робочої директорії: модифіковані файли, файли в staging area та нові файли

💡 Корисні порадки

git log - переглянути історію commit

git diff - порівняти зміни між версіями

git reset - відмінити останні зміни

git tag - позначити важливі версії проекту
